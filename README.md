# ДКМО — сборка Android-приложения

«До конца молодости осталось» — счётчик дней до выбранного возраста, личные цели
(«пока есть время») и генератор карточек/обоев с числом для шаринга.

Проект уже настроен (React + Vite + Capacitor + офлайн-кэш + локальные уведомления).
Ниже — точные команды. Выполняются на вашем компьютере (нужны Node.js 18+ и Android Studio).

## Шаг 0 — что установить один раз
1. [Node.js](https://nodejs.org) 18 или новее
2. [Android Studio](https://developer.android.com/studio) (включает Android SDK)
3. Java JDK 17 (Android Studio предложит установить сам)

## Шаг 1 — установить зависимости
```bash
cd dkmo-android
npm install
```

## Шаг 2 — проверить веб-версию локально
```bash
npm run dev
```
Откроется на `http://localhost:5173` — проверьте, что всё работает в браузере
(онбординг с датой рождения, счётчики, добавление целей, генератор карточек),
прежде чем собирать под Android.

## Шаг 3 — собрать веб-бандл
```bash
npm run build
```
Появится папка `dist/` — это то, что Capacitor обернёт в Android-приложение.

## Шаг 4 — добавить платформу Android
```bash
npx cap add android
npx cap sync android
```
Появится папка `android/` — это уже настоящий Android-проект (Gradle).

> Приложение использует нативные плагины `@capacitor/local-notifications`,
> `@capacitor/filesystem`, `@capacitor/share` (нужны для настоящего меню
> «Поделиться»), `@capacitor/haptics` (вибро-отклик при выполнении цели) и
> `@capacitor/preferences` (мост данных для виджета на главный экран).
> После `npm install` команда `npx cap sync android` подтянет их в нативный
> проект автоматически — отдельно ничего настраивать не нужно.
>
> Отдельно от этого — сам виджет на главный экран написан на Kotlin и требует
> одного ручного шага после `cap add android`, потому что нативный код нельзя
> доставить через npm. Всё готово в папке `android-widget-kit/`, подробности —
> в конце README и в `android-widget-kit/WIDGET-SETUP.md`.

## Шаг 5 — открыть в Android Studio
```bash
npx cap open android
```
Android Studio откроется сама. Дайте Gradle синхронизироваться (первый раз — несколько минут).

## Шаг 6 — заменить иконки и сплэш-экран
Сейчас стоят сгенерированные иконки-заглушки (`public/icons/icon-192.png`, `icon-512.png`,
чёрный фон + лаймовая рамка + «ДКМО»). Замените на финальные:
- В Android Studio: правый клик на `android/app` → **New → Image Asset** → загрузить свой логотип
- Сплэш-экран настраивается через `@capacitor/splash-screen` (можно добавить: `npm install @capacitor/splash-screen`)

## Шаг 7 — тест на устройстве/эмуляторе
В Android Studio нажмите ▶ Run. Подключите телефон по USB с включённой отладкой,
либо запустите эмулятор.

## Шаг 8 — собрать релизный `.aab` для Google Play
1. В Android Studio: **Build → Generate Signed Bundle / APK**
2. Выберите **Android App Bundle**
3. Создайте keystore (файл подписи) — **сохраните его в надёжном месте, без него нельзя будет выпускать обновления**
4. Соберите `release` вариант — получите `app-release.aab`

## Шаг 9 — публикация в Google Play Console
1. Зарегистрируйте аккаунт разработчика: https://play.google.com/console (разовый взнос ~25$)
2. Создайте приложение → загрузите `.aab` в раздел **Production** (или сначала в **Closed testing**)
3. Заполните карточку: описание, скриншоты, политику конфиденциальности
4. Пройдите Data Safety форму — честно укажите, какие данные собираются
   (в текущей версии — только локально на устройстве: дата рождения и список целей,
   ничего не отправляется на сервер)

## Сборка через git / GitHub Actions (без Android Studio на каждый чих)

Проект уже содержит `.github/workflows/android-build.yml`. Логика:
- **любой push в `main`** → собирается debug-APK, доступен во вкладке Actions → Artifacts
- **тег `v1.0.0` и подобные** → собирается подписанный release-`.aab`, готовый к загрузке в Google Play

### Шаг A — выложить проект на GitHub
```bash
git add .
git commit -m "ДКМО: первая версия приложения"
gh repo create dkmo-app --private --source=. --push
# либо вручную: создать пустой репозиторий на github.com,
# затем git remote add origin <url> && git push -u origin main
```

### Шаг B — проверить debug-сборку
Просто запушьте — Actions запустится сам. Через пару минут во вкладке
**Actions → последний run → Artifacts** будет `dkmo-debug-apk`. Скачайте, установите
на телефон (нужно разрешить установку из неизвестных источников).

### Шаг C — подготовить подпись для релиза (делается один раз)
1. Локально: `cd dkmo-android && npx cap add android`
2. Создайте keystore:
   ```bash
   keytool -genkey -v -keystore release.keystore -alias dkmo -keyalg RSA -keysize 2048 -validity 10000
   ```
3. В `android/app/build.gradle` внутри блока `android { ... }` добавьте:
   ```gradle
   signingConfigs {
       release {
           storeFile file(project.hasProperty('storeFile') ? storeFile : '../release.keystore')
           storePassword project.findProperty('storePassword') ?: System.getenv('KEYSTORE_PASSWORD')
           keyAlias project.findProperty('keyAlias') ?: System.getenv('KEY_ALIAS')
           keyPassword project.findProperty('keyPassword') ?: System.getenv('KEY_PASSWORD')
       }
   }
   buildTypes {
       release {
           signingConfig signingConfigs.release
       }
   }
   ```
4. Уберите `android/` из `.gitignore` и закоммитьте папку:
   ```bash
   git add -f android .gitignore
   git commit -m "Настройка подписи релиза"
   ```
5. В настройках GitHub-репозитория → **Settings → Secrets and variables → Actions** добавьте:
   - `ANDROID_KEYSTORE_BASE64` — результат `base64 -i release.keystore`
   - `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`

### Шаг D — выпустить релиз
```bash
git tag v1.0.0
git push origin v1.0.0
```
Actions соберёт подписанный `.aab` → скачайте из Artifacts → загрузите в Google Play Console.

## QR-код на карточках — как подключить реальную ссылку

Ссылка, на которую ведёт QR-код на карточках (сторис и пост), — это одна
константа в начале `src/App.jsx`:

```js
const APP_INSTALL_URL = "https://example.com/dkmo";
```

Сейчас это временная заглушка, потому что приложение ещё не опубликовано.
Как только появится реальная ссылка — на страницу в Google Play, на лендинг
или на прямую ссылку для установки APK — замените этот один URL. Больше
ничего трогать не нужно: QR-код перегенерируется автоматически на всех
карточках. Библиотека для генерации — `qrcode` (добавлена в `package.json`,
подтянется через `npm install`).

## Программа наград — как подключить реальных партнёров

Вся программа наград — это один массив в начале `src/App.jsx`:

```js
const REWARDS = [
  { id: "r1", emoji: "🌸", title: "Скидка на парфюм", brand: "Партнёр — парфюмерия", discount: "-15%", code: "DKMO-YOUTH15", url: "" },
  // ...
];
```

Сейчас там — заглушки для демонстрации механики (обобщённые названия, коды не
привязаны к реальным магазинам). Когда договоритесь с конкретным магазином:

1. Замените `brand` на реальное название партнёра
2. Замените `code` на настоящий промокод, который вам выдал магазин
3. При желании укажите `url` — ссылку на магазин/лендинг с этим промокодом
4. Больше ничего менять не нужно — выдача награды при выполнении цели,
   показ модалки, копирование кода и история наград в разделе «Цели»
   уже работают с любым содержимым этого массива

Награда выдаётся один раз на цель — либо сразу при выполнении шагов внутри
цели (когда отмечен последний), либо при ручной отметке цели как выполненной,
если у неё нет шагов. Система старается не повторять уже выданные пользователю
награды, пока не закончится пул.

## Что реализовано
- [x] Онбординг: дата рождения + выбор возраста «конца молодости» (40/50/60/свой)
- [x] Главный счётчик дней + живые тикающие часы HH:MM:SS до конца текущих суток,
      анимация «доскручивания» числа при открытии (как в Stripe/Robinhood)
- [x] Стрик — счётчик дней подряд, когда открывалось приложение (механика Duolingo),
      значок 🔥 на главном экране + модалка-поздравление и уведомление на вехах
      7/30/100 дней подряд
- [x] Relatable-сравнения — абстрактное число дней переводится в понятные вещи
      («это N воскресений», «N полнолуний», «N циклов Олимпиад» и т.д., в духе
      Spotify Wrapped), можно листать тапом
- [x] Приветствие, которое меняется в зависимости от времени суток
- [x] «Жизнь в неделях» — визуализация в духе знаменитого эссе Тима Урбана
      (Wait But Why): сетка квадратов, один квадрат = одна неделя жизни от
      рождения до выбранной границы, закрашенные = прожито. Открывается с
      главного экрана, рендерится на canvas, поддерживает скачивание и шаринг
- [x] Доп. счётчики: прожито, до 50, до 60, до конца года
- [x] Прогресс-бар «молодости» (сколько уже прожито от рождения до выбранной границы)
- [x] Раздел «Цели» — список того, что хочется успеть, с подсказками из концепции
- [x] Цели разбиваются на подцели-шаги (чек-лист внутри цели, мини-прогресс-бар,
      готовые наборы шагов для целей-подсказок — например «Влюбиться» →
      «Обновить анкету → пригласить на свидание → второе свидание → сказать, что чувствуешь»)
- [x] Награда при выполнении цели: вибро-отклик + модалка с подарком/промокодом от
      партнёра, история полученных наград сохраняется в разделе «Цели»
      (⚠️ сейчас это шаблон механики с обобщёнными заглушками-партнёрами — реальные
      промокоды нужно вписать самостоятельно после договорённостей с магазинами,
      см. массив `REWARDS` в начале `src/App.jsx`)
- [x] Генератор карточек: сторис (1080×1920), пост (1080×1080), обои телефона и десктопа —
      рендерятся на canvas и сохраняются/шарятся как PNG. На сторис и посте — QR-код
      на страницу установки (усиливает вирусный цикл из концепции: увидел у друга →
      отсканировал → поставил себе). Ссылка настраивается одной константой
      `APP_INSTALL_URL`, см. раздел выше
- [x] Настоящий нативный шаринг через `Filesystem` + `Share` (открывает системное меню
      «Поделиться» — Instagram, Telegram, WhatsApp и т.д.), с fallback на скачивание
      и понятным статусом в интерфейсе, если что-то пошло не так
- [x] Ежедневное локальное уведомление с актуальным числом дней (время настраивается)
      + уведомления на круглые вехи (каждые 1000 дней)
- [x] Полностью офлайн — всё хранится в localStorage на устройстве
- [x] **Виджет на главный экран Android** с живым числом дней — работает
      независимо от того, открыто приложение или нет, обновляется автоматически
      каждый день ровно в полночь. ⚠️ Требует одного ручного шага после сборки —
      это нативный код, который нельзя доставить через npm-пакет. Всё готово в
      папке `android-widget-kit/`, инструкция по установке — в
      `android-widget-kit/WIDGET-SETUP.md`

## Друзья — общий дашборд прогресса (готово, нужен свой Firebase-проект)

1. console.firebase.google.com → создать проект (бесплатно)
2. Build → Authentication → включить **Anonymous**
3. Build → Firestore Database → создать базу
4. Project settings → General → Your apps → Web app → скопировать конфиг
   в `src/firebaseConfig.js` (сейчас там заглушка)
5. Firestore → Rules → вставить содержимое файла `firestore.rules` из корня
   проекта, Publish

Без шагов 1–5 вкладка «Друзья» не заработает — это внешний облачный сервис,
код готов, но требует твоего собственного проекта, как и Google Play аккаунт.

Что внутри: анонимная авторизация (без email/пароля), код приглашения (6
символов), взаимное добавление в друзья, живой дашборд — прогресс по целям
друзей обновляется в реальном времени (`onSnapshot`). Точная дата рождения
не публикуется, только вычисленные дни/возраст.

## Виджет на главный экран — отдельная инструкция

Это единственная часть проекта, которую нельзя доставить через `npm install` —
нативный Kotlin-код физически не бывает npm-пакетом. Всё уже написано и лежит
готовым к копированию в папке `android-widget-kit/`:

```
android-widget-kit/
├── WIDGET-SETUP.md              — пошаговая инструкция (начните с неё)
├── DkmoWidgetProvider.kt        — вся логика виджета
├── AndroidManifest.snippet.xml  — что вставить в манифест
└── res/                          — layout, фон, метаданные виджета, строки
```

Откройте `android-widget-kit/WIDGET-SETUP.md` — там ровно 4 шага, каждый с
готовой командой для копирования.

## Структура проекта
```
dkmo-android/
├── src/
│   ├── App.jsx           — всё приложение (онбординг, счётчики, цели, карточки, настройки)
│   ├── main.jsx          — точка входа React
│   ├── LifeGrid.jsx      — визуализация «жизнь в неделях»
│   ├── notifications.js  — локальные уведомления (ежедневный счётчик, вехи)
│   ├── share.js          — нативный шаринг (Filesystem + Share)
│   ├── haptics.js        — вибро-отклик
│   └── widgetSync.js     — мост данных для нативного виджета
├── android-widget-kit/    — нативный виджет на главный экран (см. выше)
├── public/icons/          — иконки PWA/Android (сгенерированы, замените на финальные)
├── capacitor.config.json  — конфигурация Capacitor
├── vite.config.js         — сборка + офлайн-кэш (PWA)
└── package.json
```
